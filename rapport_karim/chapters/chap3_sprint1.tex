\subsection{Représentation graphique de la base de données}
La figure \ref{fig:mongodb_sprint1} présente le schéma de la base de données MongoDB mis en place pour ce premier sprint. L'architecture repose sur deux collections principales : \texttt{users} et \texttt{departments}.

La collection \texttt{users} est le cœur du système. Elle centralise tous les comptes et utilise le champ \texttt{role} pour le contrôle d'accès (RBAC). Fidèle à la philosophie NoSQL, elle intègre des documents imbriqués (\textit{embedded documents}) pour les profils :
\begin{itemize}
    \item \textbf{Socle commun} : Regroupe les informations d'authentification (email, mot de passe haché via \texttt{bcryptjs}), d'identité (CIN, nom, prénom) et les tokens de session (\texttt{refreshToken}).
    \item \textbf{Objets de profil} : Les détails spécifiques aux rôles sont stockés dans les sous-documents \texttt{student} (numéro de dossier, niveau) ou \texttt{teacher} (rang académique, spécialisations). Cette structure permet une récupération atomique des données.
    \item \textbf{Gestion des accès} : Des champs techniques (\texttt{resetPasswordToken}, \texttt{isActive}) assurent la sécurité et la gestion du cycle de vie des comptes.
\end{itemize}

La collection \texttt{departments} permet de structurer l'organisation de l'établissement. Elle est liée à la collection \texttt{users} par référence : chaque profil utilisateur contient un \texttt{departmentId} pointant vers cette collection. Inversement, un département identifie son responsable via l'attribut \texttt{headOfDepartmentId}, créant ainsi une relation bidirectionnelle cohérente.

\end{figure}

\section{Réalisation}
Dans cette section, nous présentons les principales interfaces utilisateur (UI) développées pour ce premier sprint. L'accent a été mis sur la création d'une expérience ergonomique et moderne, en accord avec l'identité visuelle de la plateforme EduGenius.

\subsection{Interface de connexion}
L'interface de connexion (figure \ref{fig:login_ui}) adopte un design moderne à double volet. Le volet gauche présente l'identité visuelle d'EduGenius avec une illustration abstraite animée et une mise en avant des piliers de la plateforme (IA personnalisée, cours de qualité). Le volet droit contient le formulaire d'authentification sécurisé. Techniquement, elle intègre une gestion d'état pour les erreurs de saisie et communique avec le contexte \texttt{AuthContext} pour initialiser la session JWT. L'interface est entièrement responsive, adaptant sa disposition pour les terminaux mobiles.

\subsection{Interface du tableau de bord}
Le tableau de bord (figure \ref{fig:dashboard_ui}) est le centre de pilotage de l'application, variant dynamiquement selon le rôle détecté dans le token JWT :
\begin{itemize}

\section{Tests}
Cette phase de tests permet de garantir que les fonctionnalités d'authentification et de gestion des utilisateurs sont robustes, sécurisées et conformes aux exigences du backlog.

\subsection{Tests unitaires}
Pour garantir la fiabilité du socle de sécurité, nous avons mis en place une suite de tests unitaires automatisés utilisant le framework \textbf{Jest}. Cette approche permet de valider les méthodes métier de manière isolée avant leur intégration dans les flux complexes de l'application.

L'accent a été mis sur la validation du modèle \texttt{User}, pilier de ce premier sprint :
\begin{itemize}
    \item \textbf{Vérification du hachage} : Test de la méthode \texttt{matchPassword} pour s'assurer qu'elle compare correctement une chaîne brute avec le hash stocké en base via \texttt{bcryptjs}.
    \item \textbf{Sécurité des accès} : Validation des scénarios de succès (mot de passe valide) et d'échec (mot de passe erroné) pour prévenir toute faille d'authentification.
\end{itemize}

\subsection{Tests d’intégration}
Cette phase de tests vise à valider la communication entre le serveur Express, les modèles Mongoose et la base de données MongoDB. L'objectif est de s'assurer que les points d'entrée de l'API (Endpoints) traitent correctement les requêtes et retournent les codes de statut ainsi que les données attendues.

Le test d'intégration majeur a porté sur le service d'authentification via l'endpoint \texttt{/api/auth/login}. À l'aide de l'outil \textbf{Postman}, nous avons soumis une requête \texttt{POST} contenant les identifiants d'un compte administrateur. Le système a validé avec succès la chaîne complète : réception des identifiants $\rightarrow$ comparaison du mot de passe haché $\rightarrow$ génération du jeton JWT.

Comme illustré dans la figure \ref{fig:integration_tests}, le serveur retourne un statut \texttt{200 OK} accompagné d'un objet JSON détaillé. Cet objet contient non seulement les informations d'identité et le rôle de l'utilisateur (confirmant l'accès au rôle « admin »), mais aussi le jeton d'authentification (\texttt{token}) qui sera utilisé par le frontend pour sécuriser les appels ultérieurs à l'API.

\section{Conclusion}

Ce premier sprint a permis de poser les fondations de la sécurité d'EduGenius. L’ensemble des fonctionnalités d’authentification et de gestion des rôles a été conçu, développé et testé avec succès, garantissant un cadre fiable pour les futurs développements. Ce socle technique assure désormais la confidentialité des données et offre une base solide pour intégrer les fonctionnalités pédagogiques des prochains sprints.

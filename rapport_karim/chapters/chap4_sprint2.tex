\chapter{Réalisation du Sprint 2 : Gestion des classes, Appels vidéo et Communication synchrone}

\section*{Introduction}
\addcontentsline{toc}{section}{Introduction}

Le deuxième sprint du projet EduGenius a été consacré à la mise en place des fonctionnalités de gestion des classes (création, planification, supervision), de communication synchrone par visioconférence intégrée avec Daily.co, ainsi que des outils de modération et de replay. Ces briques permettent aux administrateurs de structurer l’organisation pédagogique, aux enseignants d’animer des classes virtuelles enrichies (partage d’écran, contrôle audio/vidéo des participants, chat intégré, suivi de présence) et aux étudiants de rattraper les sessions enregistrées. Les notifications temps réel complètent le dispositif pour tenir les utilisateurs informés des événements clés.

Ce chapitre détaille l’ensemble des étapes ayant mené à la réalisation de ce second incrément. Nous présenterons le backlog spécifique au sprint, l’analyse fonctionnelle, la conception technique, les interfaces réalisées, ainsi que les tests effectués pour garantir la robustesse des nouvelles fonctionnalités.

\subsection{Description textuelle des cas d’utilisation}

Cette section décrit les scénarios nominaux et alternatifs pour chaque cas d’utilisation du sprint.

\subsubsection{Le cas d’utilisation « Gérer les classes et le planning » (Administrateur)}
\begin{itemize}
    \item \textbf{Acteur} : Administrateur.
    \item \textbf{Préconditions} : L’administrateur est connecté ; la matière (Subject), la classe et l’enseignant existent ; aucun conflit d’horaire n’est détecté.
    \item \textbf{Postconditions} : Une classe est créée ou modifiée avec ses horaires.
    \item \textbf{Scénario nominal} : L’administrateur suit un processus par étapes :
        \begin{enumerate}
            \item \textbf{Informations} : Saisie du titre, de l'année académique, du semestre et choix de la cible (classe ou enseignant).
            \item \textbf{Séances} : Ajout des séances hebdomadaires en sélectionnant la matière, l'enseignant, la salle et les horaires. Le système vérifie en temps réel les conflits de disponibilité.
            \item \textbf{Récapitulatif} : Vérification de l'ensemble du planning et validation finale pour enregistrement dans MongoDB.
        \end{enumerate}
    \item \textbf{Alternatives} : Code de classe déjà existant → message d’erreur ; suppression d’une classe contenant des cours actifs → confirmation requise.
\end{itemize}

\subsubsection{Le cas d’utilisation « Superviser la plateforme » (Administrateur)}
\begin{itemize}
    \item \textbf{Acteur} : Administrateur.
    \item \textbf{Préconditions} : Authentifié.
    \item \textbf{Postconditions} : Vue d’ensemble affichée (statistiques, alertes).
    \item \textbf{Scénario nominal} : Accès au tableau de bord de supervision ; le système agrège le nombre d’utilisateurs, de classes actives, de sessions vidéo programmées et de notifications envoyées.
\end{itemize}

\subsubsection{Le cas d’utilisation « Recevoir des notifications »}
\begin{itemize}
    \item \textbf{Acteur} : Tout utilisateur authentifié.
    \item \textbf{Préconditions} : Notifications activées (email ou push).
    \item \textbf{Postconditions} : Une notification est envoyée (deadline, début de cours, etc.).
    \item \textbf{Scénario nominal} : Le système détecte un événement (ex. session vidéo dans 5 min) et envoie une alerte via le canal configuré.
\end{itemize}

\subsubsection{Le cas d’utilisation « Gérer un appel vidéo » (Enseignant)}
\begin{itemize}
    \item \textbf{Acteur} : Enseignant.
    \item \textbf{Préconditions} : Une session vidéo est planifiée dans le planning.
    \item \textbf{Postconditions} : L’enseignant obtient un lien Daily.co, peut modérer les participants (micro/caméra), et la session peut être enregistrée.
    \item \textbf{Scénario nominal} : L’enseignant clique sur « Démarrer la classe virtuelle » ; le système crée une room Daily.co, redirige l’enseignant. Il peut partager son écran (US-25), couper le micro/caméra d’un étudiant perturbateur (US-26), et activer l’enregistrement (US-30). Le système enregistre l’heure d’arrivée de chaque participant (US-28).
    \item \textbf{Alternatives} : Room pleine ou expirée → message d’erreur.
\end{itemize}

\subsubsection{Le cas d’utilisation « Participer à un appel vidéo » (Étudiant)}
\begin{itemize}
    \item \textbf{Acteur} : Étudiant.
    \item \textbf{Préconditions} : Une session vidéo est active ou planifiée.
    \item \textbf{Postconditions} : L’étudiant rejoint la session, peut utiliser le chat textuel (US-27), et accéder à l’enregistrement si disponible (US-30).
    \item \textbf{Scénario nominal} : L’étudiant clique sur le lien de la session. Il peut poser des questions via le chat sans interrompre le cours. Après la session, si l’enseignant a activé l’enregistrement, l’étudiant peut visionner le replay.
\end{itemize}

\subsubsection{Le cas d’utilisation « Suivre l’assiduité et consulter l’historique » (Enseignant/Admin)}
\begin{itemize}
    \item \textbf{Acteur} : Enseignant ou Administrateur.
    \item \textbf{Préconditions} : Une ou plusieurs sessions vidéo ont eu lieu.
    \item \textbf{Postconditions} : L’historique de présence est consultable.
    \item \textbf{Scénario nominal} : L’utilisateur accède à la liste des sessions, sélectionne une session, visualise les étudiants présents, absents ou en retard avec leurs horaires de connexion (US-28, US-29).
\end{itemize}

\section{Conclusion}

Le deuxième sprint a permis de doter EduGenius d’un socle complet de gestion des classes, de planification et de visioconférence avancée. Les administrateurs peuvent structurer l’offre de formation (classes, plannings) et superviser l’activité. Les enseignants animent des classes virtuelles interactives avec partage d’écran, contrôle audio/vidéo des participants, chat intégré, et enregistrement optionnel. Le suivi de présence (détection des arrivées, retards, absence) est automatisé, et l’historique est consultable. Les étudiants bénéficient du replay pour rattraper les sessions manquées. Les notifications temps réel (US-22) améliorent l’expérience utilisateur.

Les tests unitaires, d’intégration et fonctionnels ont validé l’ensemble des douze user stories (US-4, US-5, US-6, US-22, US-23, US-24, US-25, US-26, US-27, US-28, US-29, US-30). Aucune régression n’a été constatée sur le socle d’authentification du sprint 1.

Cet incrément constitue un jalon essentiel vers une plateforme d’apprentissage hybride, prête à accueillir le sprint 3 centré sur les contenus pédagogiques, l’intelligence artificielle et l’évaluation formative.
